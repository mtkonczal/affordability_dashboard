# Demo Changes — August 11, 2026

- **Compare States gets Select all / Clear (uncommitted):** Unified Compare's picker mode into the same `multi` mode National and My State already use, so it now shows the same "Select all" / "Clear" controls. The `keep-one` mode this replaces existed because a Compare tab with zero panels had nothing to show; that's fixed by giving Compare the same empty state My State already had ("Pick a metric from the list to chart it."), so Clear can go all the way to zero and Select all can open all 14. The known cost — Select all lazy-loads 14 separate 51-state payloads and draws 14 charts at once — is now an accepted tradeoff rather than the reason the buttons were left out. Verified live (Select all → 14 of 14, Clear → empty state, removing the last metric one at a time now empties instead of refusing); all 114 tests pass, with the source-level guard pinning picker call sites updated to expect one `single`-mode call site instead of one `single` and one `keep-one`.

# Demo Changes — August 2, 2026

- **The picker now runs on all four tabs (uncommitted):** Compare States and Map lost their own rows of buttons and took the same left-hand list, so the metric control is in one place wherever a reader is. `MetricPicker` grew a single `mode` prop, because the four tabs don't mean the same thing by "picked." Compare is `keep-one`: no Clear, because a Compare tab with no panels shows nothing, and no Select all, because one click opening 14 panels — each lazy-loading a 51-state payload and drawing a chart — would look broken rather than fast. Group headers stay there (they cap at seven), guarded so that removing a group holding everything selected is a no-op rather than an empty view. Map is `single`: radio marks rather than ✓/＋, since a plus would offer a second measure the choropleth can't paint, and its group headings are plain labels for the same reason. Map lists 13 rather than 14 — index-level home prices stay out, each state being indexed to its own base year — and its collapsed menu shows the chosen measure's name where the other tabs show a count. Defaults on both tabs are unchanged: the ACA benchmark premium, one panel.

  Neither tab has a state selected, so there is no state series for a row's number to describe; both use the US figure for the metric, read from the already-loaded national payload, which is the same number the National rail prints and costs no extra fetch. The electricity bill has no US counterpart — EIA publishes state bills, not a national average — so its row reads "—" rather than inventing one. On Map the numbers follow that tab's own anchor and Real toggle, which sit down on the §02 chart controls, while §01 beside them paints state levels for a single year: two different questions, both labelled, worth knowing before reading a row as though it described the map. Cost of putting the rail beside the map: the choropleth loses about 220px (891px wide at a 1280px viewport, down from ~1111) and the Map/Bar/year controls wrap to a second line at that width. Verified live on both tabs at both sides of the breakpoint, including single-select never deselecting, the keep-one guard, deep links, and filtering; 105 tests pass, with a new source-level guard pinning four picker call sites so a fifth tab growing its own control fails loudly.

- **The picker extended to My State, and an anchor bug it exposed (uncommitted):** The state tabs now carry the same metric list as National: the same component, the same CSS, the same 1060px breakpoint, no changes needed to the picker itself. Three groups appear rather than six, and that is structural: there are no state grocery prices, and no state CPI exists, so Food and Overall inflation cannot be populated. The one judgment call was the electricity bill, the sole state metric in "Bills & getting around"; a heading over a single lone bill read like a bug, so it is filed under Rent & homes instead. That fold went into `fetch_data.R` rather than into the front end, because under the recut the category *is* the group, and a display-time merge would have put the card in the housing run wearing a "Bills" eyebrow. Cost of the fold: the state electricity card draws navy where the national one draws purple. The tab defaults to every metric on, so a reader who never touches the list sees exactly what shipped before; selection is keyed on the metric rather than the state, so walking through states with the arrow keys keeps it.

  Two things fell out of this. `ESP_METRIC_COLOR`, the by-id color map that stood in for the missing state `category`, is deleted — and it had never actually run: state cards build their item id as `il_rent` and set `category: 'state'`, so both lookups missed and every state card fell through to the pre-ESP hex still sitting in the payload. The state tab had been off-palette its whole life (indigo home prices, teal electricity, rose debt). Thirteen of the fourteen metrics landed on exactly the hex that map had been trying to give them.

  The second is a real defect the rail made visible. `anchorDate` returns a calendar date, but a series only publishes on its own schedule, and the two helpers that landed that date on a reading went opposite ways: the badges and the Copy-fact sentence took the last reading on or before it, while the chart window (and so every cumulative %-change figure) took the first at or after. Every monthly series publishes in December 2019, so nothing turned on it. FHFA home prices are quarterly: the Illinois card printed a **+55.6%** headline captioned "since Dec 2019" directly above its own badge reading **+56.3% since Dec '19** — one card, two published answers, and the headline's measured from Q1 2020, which is both mislabelled and, on a Pre-COVID anchor, not pre-COVID. `anchorObsDate` is now the single resolution every surface uses. Every number that moved moved onto the value the same card's badge was already publishing; in the default view the only headline that changes is state Home Prices, 55.6% → 56.3%. It also fixed two families of numbers that were simply wrong: annual series under Pre-COVID in %-change view were measuring from 2020 or 2021 rather than 2019 (national 20th-percentile income read +19.5% beside a badge saying +24.7%), and annual series under the 1 Year anchor were resolving to their own last reading and printing "+0.0%". "1 Year" was also quietly spanning eleven months on monthly series, because it is dated from today; it now spans twelve.

  Verified by re-running `fetch_data.R` (the data diff is exactly 14 added `category` fields, no series value moved), 104 passing tests including new `anchorObsDate` and state-parity coverage, a server-side render of the state view, and a live browser pass checking rail/headline/badge agreement across all four Nominal-Real × levels-percent combinations on both tabs, at both sides of the breakpoint and in embed mode. `source_parity.test.js` now also parses `STATE_METRICS`, which had never been checked against the committed catalog. Still needs a human pass in the ESP iframe.

- **National picker rebuilt as "the merge," and the categories recut (c18b3e0):** Replaced the National tab's collapsible category-chip bar with the design the team picked at the July review — options 6, 2 and 11 from `picker_mockups.html`, which turn out to be one component in three states. One row component in two containers: a 220px left rail above 1060px, the same rows as an "Add a metric ▾" menu below it, sharing one selection and one filter string. All 31 metrics are visible at once, grouped, with no expand step. Rows carry their change number, so the picker does the messaging before a chart is drawn — but unlike the mockup, that number follows the live anchor and the Nominal/Real toggle rather than pinning to Dec 2019, because a rail and the card it opens printing different answers to the same question is a fact-checking problem, not a styling one. Percentage points on rate series, `—` rather than a false 0.0% when nothing has published since the anchor.

  Two pieces of the mockup were deliberately not built. The sticky "jump back to the picker" bar is gone: the ESP page resizes the iframe to the tracker's full content height, so the iframe never scrolls and the parent page does — `position:fixed` inside it pins to the bottom of the whole document rather than the reader's screen, and `sticky` has nothing to stick against. It would have worked only on the standalone page, i.e. only for the version the public doesn't see. The "See all the numbers" sortable table was cut outright.

  The category recut went into the data rather than staying a display label, so `category` now decides rail group, card order and color family at once. Six ids: `housing` (Rent & homes), `groceries` (Food), `bills` (Bills & getting around), `health` (Health & care), `income` (Paychecks & debt), `overall` (Overall inflation); `big`, `daily`, `labor` and `debt` retired. Group order is editorial rather than alphabetical, with headline CPI **last** — readers come for specific items, and ending on the overall index lets the individual prices add up to it instead of trailing behind it. Metrics stay alphabetical inside each group. Merging labor and debt freed the brick family for health; `ESP_METRIC_COLOR` moved with it so a series doesn't change color between the National and state tabs. Group headers kept the comms bulk-toggle ("let me throw groceries in with Big Ticket") with the hit area on the text. Verified by re-running `fetch_data.R`, 86 passing tests including new `railChangeText` coverage, and a server-side render of `AppMain` asserting 31 rows, six groups in order, and the new labels on the card eyebrows. Still needs a human pass in the ESP iframe.
